# `.dokci`

Dokci's project (`project.yaml`): it deploys the co-op relay (`server/relay`) and the traces service (`server/traces`, under `/traces`), both at the relay's host, on every push to `main`, and each open PR's preview at a host of its own (`previews`, [`server/game-preview`](../server/game-preview/AGENTS.md)); production itself is on GitHub Pages (`.github/AGENTS.md`).

The rules across the game are the [root AGENTS.md](../AGENTS.md).

## Gotchas

- **Dokci relay TLS:** the production route in `.dokci/project.yaml` must explicitly set `entryPoint: websecure` and `certificateResolver: letsencrypt`. Omitting them creates an HTTP-only route even though the installed proxy redirects public HTTP to HTTPS; container health alone does not prove public TLS works. Keep the relay's internal HTTP port and health check unchanged, and verify trusted HTTPS at `/health` plus a WSS connection after the merged revision deploys. Never bypass certificate verification or add a public-relay fallback.
- **A new `configuration` value reaches the containers only with a deploy that's planned after it's bound.** On 2026-11-06 `LS_PREVIEWS_TOKEN` (the PR previews' old upload service's) was bound at 18:31; the redeploy started by hand from Dokci's page (#77) carried the configuration revision of the deploy before it, sat `queued` without ever running (a deploy here runs within a second of queueing and is healthy in 15 to 30 s), and once cancelled, each Redeploy failed in its "recovery phase" with no activity entry and no log. A push to `main` plans a fresh deploy (how #76 went out). Read what Dokci did with the owner's CLI (read scopes): `dokci activity list --limit 20` (each deploy's requested, queued, running, healthy) and `dokci environments show --project <id> --environment <id> --json` (each deploy's state and `configurationRevision`); `dokci projects list --json` gives the ids. A configuration change asks the owner to approve its plan in Dokci, whatever `requireManualApproval` says.
- **The traces service** has a route of its own on the relay's host (`pathPrefix: /traces`, the same entry point and resolver) and a volume (`traces-data`). Its read token is the project's `configuration` `LS_TRACES_TOKEN`, set in Dokci by the owner, never in the repo: unset, traces are still taken and kept, and nothing can read them. After it deploys, check `https://ls.wellscoped.dev/traces/health` and that the relay's `/health` and a WSS room still answer.
- **The PR previews** (`previews`, one policy, `pr`, for PRs into `main`): Dokci builds each open, non-draft PR from this repository by a collaborator from its head (`server/game-preview/compose.yaml`) and serves it at `pr-{{ pullRequest.number }}.ls.wellscoped.dev` on `websecure` with `letsencrypt` (a certificate a host, HTTP-01), and links it from the PR's "Dokci preview" check once healthy and its host resolves. It reads the policy from `main` alone, so a change to it is tried only once merged. What a preview may hold is fixed by Dokci's schema (`G:\Git\dokops`, read-only for us: `GitHubProjectPolicyReader.Previews.cs`): `trust` must be `allowForks: false` and `requireRepositoryCollaborator: true`, `cleanup.deleteVolumes` true, every resource set, no secrets or `configuration`, and only `DOKCI_SOURCE_SHA` is given to the build (no PR number). The DNS is the owner's: a wildcard `*.ls.wellscoped.dev` A record at the server, and its address in `DOKCI_PUBLIC_PROXY_ADDRESSES`. Check one with `dokci previews list`.
- **Each preview build comments on its PR** (`feedback.comment: true`, Dokci ADR 0068, since Dokci `cadd3fb`): a new comment per push, never an edit, with the link, the short commit, the time from the push to ready and the build time (or, when it failed, the reason and the check's link). It needs the Dokci App's Pull requests: Read and write, granted 2026-11-06; without it nothing fails, and the "Dokci preview" check says the comment wasn't posted and repeats the link. Like the rest of the policy it's read from `main`, so turning it off is a merged PR too. The comment code is Dokci's (`GitHubPreviewComment*` in `G:\Git\dokops`, whose AGENTS.md maps it).
