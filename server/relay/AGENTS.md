# `server/relay`

The co-op relay server (`relay.mjs`, Node and `ws`), deployed by Dokci from `compose.yaml` (`.dokci/AGENTS.md`). The game's side of co-op is `src/net/AGENTS.md`.

The rules across the game are the [root AGENTS.md](../../AGENTS.md).

## Gotchas

- **The relay server** (`server/relay/relay.mjs`, `ws://host/room/<app>/<code>?id=<peer>`): every game meets on it and every message goes through it over one WebSocket, JSON text frames; no public relays, STUN or TURN servers, and with it down there's no co-op (don't add a fallback to public ones: the owner wants only our own trusted server). Peer to peer over public Nostr relays, a player on a mobile carrier's network in Asia met the host and then never connected (ICE failed both ways: that needs a TURN server), so the server does both jobs on 443, through any network a page reaches. It checks the page's `Origin` (`ORIGINS`, where a `*` stands for one DNS label, `originsFrom`: every PR preview's host, `https://pr-*.ls.wellscoped.dev`, and every commit build's, `https://c-*.ls.wellscoped.dev`; the game's own domain, `https://last-stand.cc`, and the github.io address
it moved from, whose old tabs and installed apps may still be open; set as the domain came, co-op there was turned
away with a 403 till the relay was deployed again), holds 4 peers a room, caps each socket's messages and bytes a second (far over the co-op chat's own limits, which every game holds itself: `src/net/AGENTS.md`), answers the game's pings (the round trip), and holds a dropped peer for `GRACE` so a reconnect with the same id is unseen. A restart loses its rooms: every game reconnects on its own for `RECONNECT`, and a partner missing after a reconnect has `GRACE` to come back before it counts as gone (told at once, the guest took the host as gone and left the room before the host was back). Dokci deploys it from `.dokci/project.yaml` (`server/relay/compose.yaml`, routed by Traefik to `ls.wellscoped.dev`) on every push to `main`. The game is built for `VITE_COOP_SERVER` (default `wss://ls.wellscoped.dev`), `?server=` tries another, and the invite link carries it. The co-op dialog asks the server's `/health` as it opens (`serverUp`, which the server answers with CORS for its `ORIGINS`) and, with no answer, says the server is offline, with Try again, Host and Join disabled; a room that can't reach it says the same (`ServerDown`, `SERVER_DOWN`), not an error. Test locally with `cd server/relay && npm i && ORIGINS=http://localhost:5199 PORT=8787 node relay.mjs` and `?server=ws://localhost:8787`, two browser contexts driving the page's own UI (an `import()` from a probe can get a second copy of a module), and a restart of the server under a joined room.
- **Rooms, the public list and passwords** (`rooms.mjs`, #676): a host opens its room with `&host=1` and its flags on the socket's address (`pub=1` listed, `lock=1` a password, `max=2..4` how many it holds; never the password itself, which comes in the host's first message, `{ t: 'lock', pw }`, over the encrypted socket, and is kept only as a salted scrypt hash). A joiner of a locked room is asked (`{ t: 'locked' }`) and answers `{ t: 'pass', pw }`; a wrong one is turned away (`{ t: 'denied', why }`, closed 4003), and one address has `TRIES_PER_MINUTE` (5) wrong ones a minute. A peer back within the grace needs no password again. A listed room's host sends its card (`{ t: 'card', c }`: its name, the host's tag and class, map, wave, lobby, protocol) on opening, as it changes and every 20 s; the relay keeps only what `cardOf` cleans (no control or format characters, each part held to its size) and drops a card not sent within `CARD_TTL` (75 s). Only the room's host may lock it or send its card. `GET /rooms?app=` lists the rooms of the asking page's own site (its `Origin`, `www.` left off: a PR preview's rooms are its own and never production's) and app, with a live host and a fresh card, the players counted by the relay itself, never the password or its hash; one address may ask `LISTS_PER_MINUTE` (120) times. A host can't open a room another host holds (`taken`); a room past its `max` turns a joiner away (`full`); a game of the relay before rooms meets by its code as ever (no `host=1`), and the relay's `hi` says `v: 2` so the game can refuse to open a public or password room on an older relay, which would let anyone in. Everything is in memory: a restart loses the list, and each host sends its password again on its next `hi`.
- `startRelay(options)` runs it in-process (the tests and `lab rooms`); run as a script it's the deploy's. `faults` (`anyPassword`, `listPrivate`) are the lab's canaries alone, never set by the deploy. Tests: `npm run relay:test` (once: `npm ci --prefix server/relay`), through real sockets; the PR build runs them. No new setting or secret: the deploy is the same compose, its image now also copying `rooms.mjs`.
