# `server/previews`

The PR previews service (`previews.mjs`, Node with no packages; `serve.mjs` starts it; `tar.mjs` reads the archives it's sent): each PR's builds, sent by `pr-preview.yml` (`scripts/preview`), kept and served as static files under `/pr-preview` on the co-op relay's host. Deployed by Dokci beside the relay, from the relay's `compose.yaml` (`.dokci/AGENTS.md`). Why it exists: GitHub Pages held each preview's deploy in its queue for 100 to 330 s, sometimes over 600 (measured 2026-11-06), and its CDN kept a path's old copy for up to 10 minutes; here a build is served the moment its upload answers, about half a second for the game's 53 files (9.6 MB) on the owner's machine.

The rules across the game are the [root AGENTS.md](../../AGENTS.md); how the previews are published is [`.github/workflows/AGENTS.md`](../../.github/workflows/AGENTS.md).

- `GET /pr-preview/pr-N/` the stable page (`.github/preview-index.html`, main's copy, sent with each publish), `/pr-preview/pr-N/latest.json` what it goes by (never cached), `/pr-preview/pr-N/<sha7>/...` a build. `GET /pr-preview/health`: `ok`.
- Behind the token (`Authorization: Bearer <PREVIEWS_TOKEN>`): `PUT /pr-preview/api/pr-N/<sha7>?sha=<sha>` a build (a gzipped ustar of its folder), `PUT .../pr-N/latest.json`, `PUT .../pr-N/index.html`, `DELETE .../pr-N`, `GET /pr-preview/api/previews` (what's kept). Unset, the API is off and what's kept is still served.
- Tests: `npm run previews:test` (the PR build runs them): what it takes and turns away, the token, what it serves and how, what it prunes. `npm run lab -- pwa` sends two preview builds of this tree to one started in its process and visits them as a player does (the stable page, the worker, offline, pruned, a closed PR's). `npm run preview:test` runs the workflow's scripts against it.

## Gotchas

- **A build is plain files, nothing else** (`tar.mjs`): a link, a device, a pax or long-name entry, a path that climbs out or names a hidden file (`.git`), or a gzip that unpacks past `MOST_UNPACKED` turns the whole upload away (400, 413). It's unpacked beside (`.incoming/`) and moved into place whole, so a build is served whole or not at all, and an upload cut off by a restart is cleared at the next start. Its compressible files get brotli and gzip copies beside it (`.encoded/`, never served by path), sent as the browser accepts them; `assets/` (named by their contents) are kept a year, everything else is checked again each time (`no-cache` and an ETag), the worker included, so a plain reload shows a new build.
- **What it keeps:** the builds in the `previews-data` volume at `/data`, each PR its newest `KEEP` (3) and never the one its `latest.json` names (a stable page sent to a pruned folder is sent back to the stable page, round and round); past `DISK_MAX` (2 GB), the oldest of all go but each PR's newest and named. `pr-preview.yml` removes a PR's previews once it's no longer open.
- **What's gone:** a pruned build's page goes to its PR's stable page, a gone PR's to the game (`SITE`); a file a page asks for that's gone is a 404. An installed app or a link left on an old build lands on the newest.
- **Origin:** the previews share the relay's origin (`https://ls.wellscoped.dev`), so the relay's `ORIGINS` (and the traces service's, #349) include it for co-op from a preview. They no longer share production's, so a preview has its own saves, and production's worker and caches never meet a preview's. A fork's build runs on this origin: nothing here reads a cookie, and the token is a header the workflow alone sends.
- **The token is the owner's**: Dokci's `LS_PREVIEWS_TOKEN` (`.dokci/project.yaml` `configuration`) and the same value as the repo's `pr-preview` environment's `PREVIEWS_TOKEN` secret, never in the repo. Compared in constant time.
- **On Windows a folder of files just written may not move at once** (its scanner or indexer holds one): an upload answered 500 (EPERM) in a few, and the tests flaked. Every move is tried again for up to a second (`moveWhenFree`); Dokci's Linux never meets it.
- Run it locally with `DATA=.tmp/previews PREVIEWS_TOKEN=dev PORT=8789 node server/previews/serve.mjs`; on Git Bash, set `MSYS_NO_PATHCONV=1` for anything given a `/pr-preview/...` path (a Vite `--base`, `PAGES_BASE`): Git Bash rewrites it into a Windows path.
