# `src/dev`

The developer mode: a free camera with the game frozen, and a panel to set up anything to test and see what a moment costs. From the owner's ask: "add free cam mode (and freezing the game) while flying around, for devs. And just in general have a locked developer mode, where you can test what ever you wish (set the wave, have all gear, and so on). Would make testing easier, especially for performance and finding whats causing it."

The rules across the game are the [root AGENTS.md](../../AGENTS.md).

> **Only on PR previews and in dev builds. NEVER in production: the live game must not have a byte of it.** Keep both locks below, and check a production build has none of it after any change here, to `main.ts`'s loading of it, to `vite.config.ts` or to the preview's Dockerfile.

- **Locked to dev builds and PR previews, absent from production.** `main.ts` loads `index.ts` by a dynamic import behind `import.meta.env.DEV || __DEV_TOOLS__`. `__DEV_TOOLS__` is a Vite define (`vite.config.ts`), true only when the build has `BUILD_PREVIEW=1`, which the PR preview's Docker build alone sets (`server/game-preview/Dockerfile`); production's (`deploy-pages.yml`, `npm run build`) doesn't, so the branch folds to `false` and the chunk and its stylesheet are never made. A second lock at run time: outside a dev build the host must be a preview's (`pr-N.ls.wellscoped.dev`, a commit build's `c-….ls.wellscoped.dev`) or this machine's (the preview's image tried locally). Check a change keeps production clean: `npm run build`, then search `dist/` for the panel's strings (`Stash every base`, `dev-panel`): none; `BUILD_PREVIEW=1 npx vite build --outDir <tmp>` has them in a `dev-*.js` and `dev-*.css` of their own.
- **No shared system knows about it.** `main.ts` hands it the game's own flows (`DevHooks`: a run at a wave, a class switch, gear changed, the top view, the fight's warm-up) and asks three things a frame (`DevApi`): the game's step (`simDt`: 0 frozen, a share slowed or sped, one step of 1/60 s while frozen), the free camera placed after the game's own camera (`frame`, by the browser's clock so it flies frozen), and whether the cursor is wanted (the close views' mouse look then doesn't hold the pointer). God mode wraps `Player.prototype.takeDamage` from here (a hit on the local hero doesn't land, as a guarded one doesn't). `makeItem`'s optional `base` is the one change to shared code it needed.
- **Keys:** F8 the panel, F9 the free camera (from the top view, frozen), F7 freeze. Flying: WASD / arrows, Q down, E up, a drag (any button, or a finger) looks, the wheel steps the speed, Shift fast, Ctrl slow, F freeze, `.` one step, R back over the hero. The hero stands idle while it flies (`player.idle`, set each frame: closing the pause menu clears it). On touch the DEV tab at the left edge opens the panel, and flying shows buttons for the moves, Freeze and Leave (`#dev-fly.touch`).
- **World labels** controls the overlay draw both in play and in flight. Labels start enabled; while flying, `updateFloaters(0)` projects them again after the free camera moves, including while frozen.
- **What it costs:** the panel's Performance section shows the frame's draws, triangles and programs, switches the performance overlay's size, takes the frame's parts out live (the profiler's, `perf/sceneParts.ts` `frameParts`, each changed with the scene's programs kept, the lit-shading-against-a-plain-colour part left out as it compiles programs of its own; its part of what's cut out given as Trees, Leaves and Grass, `marked.ts`), and times them: **Profile this spot** runs the profiler on the panel's parts alone (`profile`'s `parts`), every part in and then each taken out and put back in turns, from wherever the camera is, the free camera's spot too, and shows each part's milliseconds beside its checkbox (the frame with it less the frame without; from the owner: "profile this spot button in dev tab should add ms per frame to each of the checkbox... it should not open pause menu on the performance tab"). It stays in the panel and sends nothing; its button reads Stop with how far it is, and stops it. A part is named without its count (`the particles (3)`), which changes as the scene does.
- **Nothing it does compiles mid-game:** a wave in another biome and a foe of another biome go through the fight's warm-up (`whenFightWarm`), gear and class switches through the lobby's own paths, whose models were warmed with everything they can wear. Checked: the program count held at 168 through a run in another biome, five spawned foes, the three warrior styles at Ascendant, a class switch and back.
- **Saves:** the gear and records it makes are saved as play saves them, into that host's own storage: a preview's or the dev server's, never production's.
- Its look is `dev.scss`, imported by `panel.ts` (on the theme, `zoom: var(--ui)` with px inside; the panel scrolls within the window's height and takes a narrow screen's width; the fly layer sits over the hero selection screen, under the modals).
- **Hero / Dev tabs** share the lobby's left panel; outside the lobby the developer panel floats on the left, leaving the stash side clear. Opacity is in the top-right header and fades the whole panel, controls and text included, from 50% to 100%. Native select options have an explicit dark background.
- Collapsed Hero and Dev entry tabs stack down the left edge, each reopening its own content. The Dev panel has no X; F8 and the tabs switch it. Its scrollbar stays thin and in the theme when undocked for free flight. The developer panel does not release first/third-person mouse look; Alt shows the ordinary UI cursor. Only free flight asks for an unlocked pointer.
- `help.ts` installs the developer shortcuts in pause Controls, a prominent Dev mode enabled label on every pause tab, and a DEV MODE prefix on the build footer. The controls page scrolls inside its own area so help cannot overlap the footer. All of this is generated by the dev module and absent from production.
- **No costs** is its own persistent toggle, not `player.sandbox` (the lobby and run flow overwrite that field). Every rendered frame refills Energy and clears cooldowns, including frozen frames. Starting a wave or changing Training during a run releases frozen flight. Reset restarts the loaded wave (same biome and training mode) or restores the lobby, reviving the hero and restoring normal time; it does not roll back saved gear.
- **Performance inclusion** uses two columns of checked-by-default boxes: uncheck to remove work. The button offers Uncheck all when everything is included, otherwise Check all. Full resolution is the inverse of the profiler's half-pixels experiment. Reset, a biome change and new runs restore removed parts, but Trees, Leaves and Grass, which hold (their marks are the same everywhere); Check all restores them too. The list reads, two to a row: Full resolution, Point lights, Shadow maps, Particles, Hero, Trees, Leaves, Grass, Smoke & effects, Fire, Arrows on ground. Compact FPS/frame-time statistics sit beside Performance; CPU/GPU/p95/draws/triangles/shaders and memory counts use the main performance HUD's live timings, collected while the panel is open even if the separate overlay is off.
- **Manual Training spawns** read the checkbox for +1/+5/+20 and Elite spawns, including in the lobby. The per-enemy training flag makes them ghost projections with zero attack damage, excludes their rewards and follows summoned children and co-op spawn reports. Toggling Training in an existing run still restarts that wave in the selected mode.
- Gear shares rows for rarity/weapon style and slot/base/Wear/To stash. The pause help separates general developer shortcuts from free-camera controls.
- The header's Opacity control fades the complete panel, not only the backing. Control text is 15 px with a fixed 28 px button height. An explicit sticky Scroll for more cue appears while content remains below; the scrollbar reserves its gutter.
- Opacity is applied to independent controls and text groups, with the backing faded separately: a hovered element returns to opacity 1 while its neighbours retain the slider value. An ancestor opacity would cap the hovered child's brightness. Stable opacity layers, fixed metric line heights, tabular digits and updating existing value nodes keep hover and live samples from shifting the layout; scroll anchoring is off within this tool panel.
- Speeds, blue Freeze and Step share one row; Free camera, Back to hero, World labels and Hide UI share another. Profile this spot is on the Overlay row. Metrics use two rows of four columns, with no extra inclusion hint.
- Training's label and the biome select work through the Alt cursor during normal and Training runs. Developer wave restarts preserve held Alt so the cursor stays active between controls; dropdown selection gives keyboard focus back to play. Hover brightness also follows the Alt cursor's `alt-hover` state.
- The biome picker applies immediately, including mid-run, through `biome.ts` after fight warmup. It replaces standing enemies by roster counterparts, preserves ids/positions/health shares/Elite/Training, remaps queued and gate-scheduled spawns, and leaves the run, bag, score and wave intact. Transient attacks are cleared; co-op receives the arena swap before replacement spawn reports. This action is exposed only by the dev module.
- **Trees, Leaves and Grass** (`marked.ts`, checkboxes in the frame's parts; from the owner's asks: "add feature to dev mode, where you can toggle to remove trees, on or off", then "we need 3 checkboxes, trees, leaves, and grass, separately") each take what a builder marked out of what's drawn everywhere at once, the biomes and the village, or put it back. Trees: the Thornwood's ring of trees and its giants, its young oaks in the clearing, the crypt's dead trees beyond the wall and the small ones on its floor with their roots, the village's trees (`asTree` in `world/props.ts`, the copies casting their shadows too), their leaves with them. Leaves: every mesh drawn in a material marked as leaves' (`asLeaves`: the trees' leaf cards, the gates' arches' canopies, ferns, fallen leaves, ivy), the bark left standing. Grass: the Thornwood's tufts, the crypt's weeds, the village's meadow (`asGrass`): it isn't cut out, so the profiler's part of what's cut out ("Leaves & grass" here before) never held it. Rocks, stumps, logs, the thicket's cores and the sunbeams stay. By their layer (`HIDDEN_LAYER`, which no camera draws; each object's own layers kept and given back as its last mark comes back), never `visible`: a culled mesh's is the culling's own, set again as its cells come into view, and a shadow copy's the shadow map's (the profiler's own part of what's cut out hides by `visible`, which a culled mesh's cells put back as the camera moves). So the sun's shadow map leaves them out with the frame, and the still shadows are drawn again as one is clicked (`G.arena.stillShadowsChanged`; the village's lamps' map of still shadows, drawn once at boot, keeps them); the programs and the lights are the same either way. Only what's drawn changes: a tree taken out still blocks bodies, arrows and the foes' paths where it stood (the wall's shape, the obstacle circles and the navigation grid are the game's own, shared in co-op), and a young tree's dark patch on the floor (`contactShadows`) stays to say where. Each holds through a biome change, a run's start and Reset, isn't kept over a reload (as God mode isn't), and nothing of it goes over the link.
- `npm run lab -- dev --cold --canary` checks Trees, Leaves and Grass where the lab boots and in another biome (each out and back, its draws in the pictured frame, held through the biome change, no program made; the canary one of each left drawn), Profile this spot (every part timed in the panel, on short turns by the browser's clock, `panelProfile`; the pause menu left closed), and the real controls, the five UI viewport sizes, a training start from frozen flight, refills, recovery from death, and head layers during 0.1x first-person entry. A cold boot avoids waiting for unrelated other-hero warmups; the Start control still waits for the fight's real warmup. Pictures are in `tools/lab/out/dev`.

- `placeFreeCam` puts the free camera at a place and a way to look, for a harness's flight: `npm run lab -- perf --village --fly` flies it over the village and times every frame (`tools/lab/commands/perf.md`).
